# M4.1 摘要可靠性与协作对照

状态：候选修复已通过离线与工具协议验证，真实开发集评测进行中。正式结果和生产更新在完成后补入，不能将下述机制或离线测试当成质量优势。

## 本次改变

新任务可选择单 Agent、精简协作、完整五阶段。精简协作只调用规划、执行、审查模型；分配由程序验证依赖及写入范围。不同模型的绑定在任务开始时冻结，不在运行中暗中切换。

v4 复用 LangGraph 每次调用独立的子图检查点。两个执行子任务只收到自己的要求、验收和必要依赖；完整公开结果保存为可按需读取的工件。原 v3 检查点继续使用旧合同，不能自动迁入新图。

审查接收本 Run 的实际工具记录、源码版本、命令和日志。命令快照只能证明初始副本，执行期间代码可能变化，因此模型审查与独立隐藏验收分开记录。

context-v2 将摘要正文目标设为约 1200 tokens，生成上限仍为 4000。只有明确因输出额度截断且窗口允许，才以相同来源恢复一次至 8000；每 Run 共享一个恢复名额。超时或结果未知不重发。主回答输出上限保持 100000。

v2 使用明确标注的 Unicode 加权估算，减少旧字符估算的过度压缩；对无新增来源、压缩收益不足的摘要保留证据并避免重复付费。原始记录及工具配对保留，不声称这是供应商精确 tokenizer。

2026-11-09 的真实摘要模式探针：Flash 接受参数但仍观察到推理，标记不支持；Pro 接受参数但观测不足，标记未知。两者摘要暂继承原推理模式，不因 HTTP 成功宣称关闭思考。工具往返均通过；共计 6 次模型请求纳入统一账本。

## 对照口径

| 条件 | 实际流程与模型 |
|---|---|
| Single-Pro | Pro 单 Agent，自主读、改、测 |
| Single-Flash | Flash 单 Agent，同样工具及权限 |
| Full-Pro | 五阶段全部使用 Pro |
| Compact-Pro | 规划、执行、审查均使用 Pro |
| Compact-Mixed | Pro 规划和审查，Flash 执行 |

每个条件使用相同 context-v2、100K 主输出、50 次模型请求、100 次工具调用、1800 秒活跃时间上限，以及同一固定沙箱镜像。最多两个独立子任务并行；重叠或不明确的写入范围串行。代码通过受控补丁修改，命令与验收只在过滤后的快照运行。

开发集 3 题 × 5 条件，共 15 Run。开发完成后冻结实现、模型配置和任务。正式集 6 题 × 5 条件 × 3 次重复，共 90 Run；每个任务与重复构成一个五条件块，按固定顺序执行。最高 105 Run、1500 次模型请求，包含失败、摘要和恢复；余额不足预留下一 Run 的 50 次额度时停止，剩余明确标记未运行。

| 复杂度 | Python | TypeScript |
|---|---|---|
| 低 | 严格时长解析与边界 | 精确金额汇总与非法输入 |
| 中 | CSV 汇总库、CLI 和一致错误处理 | TTL/LRU 缓存与注入时钟 |
| 高 | SQLite 迁移、事务回滚、兼容 CLI | 多模块离线报告流水线与集成 |

复杂度是本组小型代码题的相对等级，不等于大型真实仓库。每题有五组等权需求。隐藏验收不交给模型，也不反馈后再让模型修到通过。9 个开发/正式题的参考实现与缺陷版本已在固定工具镜像分别运行：参考 9/9 通过、缺陷 9/9 失败。TypeScript 实际执行固定 tsc，不能用类型擦除代替类型检查。

## 指标的含义

- 质量：同时记录流程是否结束、代码是否通过、类型检查、五组需求分数。主成功标准是流程完成且全部隐藏验收通过。
- 费用：逐模型操作计算公开最高档、无缓存折扣、未乘账户组的参考单位；所有失败开销保留，推理 tokens 不重复计入输出。没有账户账单对账，因此不是实扣人民币。缺失用量保持未知，不填零。
- 耗时：提交到终态的墙钟时间，另列排队、阶段区间并集、摘要、工具及独立验收。只有同题双方都成功才比较速度，失败不能算更快。
- 结论：按复杂度列结果，并按同题同重复成对比较。质量不下降且费用或耗时至少一项改善才描述该题上的优势，同时说明另一项是否变差。三次重复用于展示波动，不作通用排名或统计显著性主张。
