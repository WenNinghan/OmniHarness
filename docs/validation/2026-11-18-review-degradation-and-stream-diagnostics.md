# 流完整性细分诊断与审查降级交付验证说明

日期：2026-11-18（Asia/Shanghai）。状态：开发预览，离线验证与回归检查完成，尚未宣称真实模型长流稳定性问题已彻底消除。本文不包含任何真实供应商地址、本机路径、运行标识、凭据或原始模型响应。

## 本次变更解决什么

在先前的开发任务测试中，执行阶段已完成代码修改并通过测试后，后置独立审查阶段偶发出现两类影响整单交付的问题：一是长流式响应触发完整性守卫（此前脱敏诊断仅归类为笼统的 `PROVIDER_ERROR`）；二是审查模型因代理超时、截断或返回非 JSON 文本，直接导致已完成代码的任务整体失败或停留在待核对状态。此外，离线工作区压力测试和前端构建还遗留了少量已知边界待收尾。本次更新在不放宽任何安全边界的前提下逐项处理：

- **流完整性细分诊断与兼容终态对齐：** 在原生流式聚合器中对齐标准输出模块支持的合法终态同义词（如 `end_turn`、`stop_sequence`、`max_tokens` 及大小写变体），使正常结束或达到输出上限的响应保留已收到的内容并进入既有截断/过滤分类；对真正的流不完整故障保留 `OUTPUT_INCOMPLETE` 与 `UNKNOWN` 不重放语义，并在脱敏诊断中记录固定有界枚举 `incomplete_reason`（区分 `missing_finish`、`invalid_finish` 与 `conflicting_finish`），不记录任何响应正文或异常文本。
- **可选的审查失败降级交付（`deliver_unreviewed`）：** 新增显式开关 `OMNI_REVIEW_FAILURE_POLICY=deliver_unreviewed`（默认保持 `fail` 不变，仅在开启后随新建的 `v4`—`v6` 多阶段任务快照冻结）。当执行结果已保存，且宿主核验不存在任何结果不明的工具操作、工具占槽或其他阶段未知调用时，若审查阶段发生格式无效（`INVALID_OUTPUT`）、输出截断（`INCOMPLETE`）、外部请求结果未知（`UNKNOWN`）或审查前预算耗尽（`NOT_RUN_BUDGET`），宿主记录 `agent.review_degraded` 事件与 `UNAVAILABLE` 占位，将任务结算为 `completed` 并附带显式 `review_status`。原未知审查请求继续保持 `uncertain`，绝不自动重发；取消、暂停、失锁、栅栏错误及崩溃后重入已预约操作仍严格停止，不被降级吞没。
- **界面提示与评测口径隔离：** 消息气泡、复制文本与运行详情面板同步展示显式的「审查未完成」提示，保留已落盘的原始审查工件供人工核查。评测聚合将 `delivered_unreviewed`（未审查交付）单独计数，`resolved`（完整交付）继续严格要求流程完成、独立审查未降级且隐藏验收通过；评测计划在保留 `context-v2` 默认契约的同时，支持显式指定 `context-v3` 统一公平性校验。
- **工作区边界与前端分包：** 补齐 Windows 保留设备名对上标数字（`COM¹`、`COM²`、`LPT³`）及 `CONIN$` / `CONOUT$` / 扩展名前尾随空格的预校验；将多实例并发复用同一操作标识创建恢复目录时的竞争异常统一映射为 `WorkspaceError("operation_exists")`。前端构建按依赖拆分 `vendor-react`、`vendor-markdown` 与 `vendor-icons`，消除大于 500 kB 的单包体积提示。

本次更新未新增外部依赖，未修改数据库表结构，也未发起任何付费外部模型调用。

## 验证范围与边界

- **后端静态检查与回归测试：** Ruff 检查通过；新增及既有协议、流诊断、阶段编排、工作区并发与评测契约测试通过，覆盖三种流不完整细分原因、兼容终态同义词、四种可降级审查故障、三种不可降级安全阻断（未知工具占槽、运行取消、崩溃窗口重入）、设备名预校验及同操作标识八路并发竞争。
- **前端测试与构建：** 前端纯逻辑单测（含新增审查降级状态识别与剪贴板提示保留测试）全部通过，TypeScript 编译与 Vite 生产分包构建通过且无大包告警。
- **明确未覆盖的范围：** 本轮未发起真实供应商 API 请求，尚未在真实模型线路上做全阶段原生流式能力探测，也未对已观察到的长流提前结束现象给出上游根因结论；启用 `deliver_unreviewed` 只避免后置审查单点故障掩盖已完成代码，不能把未审查交付等同于独立审查通过。
