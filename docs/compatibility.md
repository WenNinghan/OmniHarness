# M0–M2 兼容性与验证记录

记录日期：2026 年 11 月 5 日。版本：`0.1.0a1`。这是本地预览版的能力记录，不能据此推断后续多 Agent 工作流已经交付。

## 当前产品范围

| 能力 | 当前行为与边界 |
|---|---|
| 本地控制台 | React/Vite 静态 Web，由 FastAPI 同源提供；当前没有桌面安装器 |
| 配对与访问控制 | 一次性配对码、HttpOnly 会话 Cookie、Origin 检查和修改请求标识；默认只开放本机回环地址 |
| 模型配置 | 支持新增、更新、禁用、配置版本、API Key 加密存储；省略 Key 保留旧值，空串清除 |
| 配置导入导出 | 带 `schema_version`；导出无凭证，导入创建独立配置并要求另填真实 Key |
| 聊天执行 | API 将请求入库，独立 Worker 顺序执行；重复请求 ID 复用原 Run，冲突内容被拒绝 |
| 流式输出 | 已保存文本与 Run 事件可查询，SSE 可从游标补拉；负数、格式错误和超出范围的游标被拒绝 |
| 停止与恢复 | 可取消排队/运行任务；Worker 重启后在途请求标记为 `interrupted` 并保留已保存文本，不自动重发收费请求 |
| 模型停用 | 已停用模型的排队请求在发送前失败，不继续使用排队时保存的启用状态 |
| Mock 演示 | 显式标记模拟模式；不消耗真实模型配额，不提供虚假成本或真实能力验证结论 |
| 插件 | 已提供 Python 协议、API 版本检查、入口点发现和一个确定性 Verifier 示例；发现成功不等于获得执行权限 |

真实模型未配置 Key 时不会自动切换 Mock。模型运行使用入队时的配置快照；编辑配置不悄悄改变已排队请求，停用检查仍以当前状态为准。

## Provider 验证

| 接入方式 | 实际验证 | 适用边界 |
|---|---|---|
| OpenAI-compatible | 使用 `https://e-flowcode.cc/v1` 的 `deepseek-flash` 实际请求验证了 chat、streaming、tools 和 structured 四项探测 | 只代表该 Endpoint、该模型和本次探测配置；不代表所有兼容网关或该 Provider 下所有模型 |
| OpenAI 原生适配器 | 构造参数、消息/流式结果和错误处理经过离线契约测试 | 未使用 OpenAI 官方 Endpoint 的真实 Key 验证 |
| Anthropic 原生适配器 | 构造参数、协议分支和错误处理经过离线契约测试 | 未使用 Anthropic 官方 Endpoint 的真实 Key 验证 |
| Gemini 原生适配器 | 构造参数、协议分支和错误处理经过离线契约测试 | 未使用 Google 官方 Endpoint 的真实 Key 验证 |
| 本地或其他 OpenAI-compatible 服务 | 可配置明确 Endpoint；允许本机 HTTP 地址，远端地址要求 HTTPS | Ollama、vLLM 及其他具体部署未在本轮运行验证 |
| Mock | 已验证离线回复、持久化事件中的模拟标记，以及未知费用不冒充实测值 | 不提供真实 Provider 能力证明 |

`tools` 探测检查模型能否返回并衔接工具调用协议，`structured` 探测检查本次结构化输出约束；它们不表示产品已经开放 Shell、MCP 或沙箱工具执行。

## 框架与自动化测试

本轮实际安装环境为 Python `3.12.13`，主要运行库为 Deep Agents `0.7.32`、LangGraph `1.2.20`、FastAPI `0.162.0`、SQLAlchemy `2.1.8` 和 Pydantic `2.14.2`。完整依赖由根目录 `uv.lock` 固定，前端依赖由 `web/package-lock.json` 固定。

自动化验证使用显式启用的 SQLite 临时测试库，覆盖配对码重放/过期、会话撤销、跨站与缺失请求头、密钥脱敏与加密、配置导入隔离、消息幂等、队列上下文顺序、取消与流关闭、SSE 游标补拉、重启中断标记、停用模型阻止发出请求及插件错误隔离。

`scripts/runtime_probe.py` 使用确定性的本地测试模型，实际驱动已安装的 Deep Agents 工具循环与两个子 Agent 并行，并验证 LangGraph 在 SQLite 检查点关闭、重新连接后的中断恢复。这个探针验证框架运行机制；它没有验证真实模型的规划质量，也没有把完整多 Agent 调度接入当前聊天产品。
