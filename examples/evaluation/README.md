# 首批固定回归任务

`tasks.json` 提供 20 项可执行的固定任务：10 项研究任务、5 项 Python 修复任务和5 项 TypeScript 修复任务。任务 ID 固定，输入与预期结果随 `dataset_version` 一起版本化。

所有研究资料均为自编合成材料，资料标题、主体、数字和实验记录不对应真实来源。资料中的 `document_id:line` 是本任务集的内部定位符，不是网页引用。代码也是自编缺陷练习。不要将这些材料作为真实研究证据发布。

## 数据字段

| 字段 | 用途 |
|---|---|
| `id`、`category`、`language` | 稳定任务标识、研究/代码类别、代码语言 |
| `input` | 完整指令、所需资料或有缺陷源码，以及任务约束 |
| `acceptance_criteria` | 必须满足的验收条件 |
| `verification_method` | 研究结果核对方法，或可以独立执行的测试代码 |
| `expected` | 可核对的数值、证据定位、状态、输出与异常类型 |

研究任务覆盖单位换算、分母、缺证据 `UNVERIFIED`、来源冲突、时间截止、引用定位、同名主体隔离、转载去重、缺失值和局部退化。除明确的截止后资料排除任务外，不得丢弃输入记录来美化结果。

## 手工执行方式

1. 选择一项任务，把 `input` 交给待测系统。研究任务仅允许使用所附材料；代码任务保留函数接口和测试条件。
2. 保存输出、所用模型/配置、数据集版本和任务 ID。不要把 `expected` 当作提供给待测模型的提示词。
3. 研究任务逐字段核对预期，允许等价自然语言，但数值、单位、证据状态和引用位置必须正确。默认浮点绝对容差为 `1e-9`；任务另行规定时采用任务值。
4. Python 任务将修复结果保存为 `candidate.py`，将 `verification_method.test_code` 保存为同目录 `test_candidate.py`，用 Python 3.12 运行。断言只使用 Python 标准库。
5. TypeScript 任务将修复结果保存为 `candidate.ts`，测试保存为同目录 `test_candidate.ts`，在隔离测试目录用工程已有的 TypeScript 工具链编译后运行。测试使用 Node.js 标准库 `node:assert/strict`，目标至少 ES2022；无需第三方运行库。测试中的 `./candidate.js` 指向编译产物。

有缺陷的原始代码预计不能通过全部断言。应修复实现，不应删除断言、改小输入范围或硬编码几个样例。涉及异常的任务必须满足指定异常类型。

## 结果边界

这是回归任务集，不是性能报告。本次已校验数据结构、分类数量、ID 唯一性、资料引用和 Python 源码/测试语法；5 组 TypeScript 候选源码及其测试均通过项目已有 TypeScript 7.0.2 的 `--noEmit` 检查，启用 `strict`、ES2022 和 Node 类型。检查文件保留在 `.omniharness/eval-ts-check`，未执行缺陷候选代码或断言，也未安装新依赖。

没有执行 20 次真实模型评测，也没有模型成功率、延迟或成本结论。编译通过只证明类型与语法可检查，不代表有缺陷的初始代码通过功能验收。

完整 20 任务的 M5 自动评测 Runner 尚未实现。M4 已新增一个范围明确的代码链路 Runner：只选择 `python-001` 和 `typescript-001`，通过现有 API 比较单执行 Agent、同模型五阶段、多模型五阶段，并在工作区外的独立沙箱运行隐藏验收。用法、证据字段和限制见 [M4 评测说明](../../docs/M4-evaluation.md)。默认只描述计划，显式执行才调用模型，不自动安装依赖。这个六次 Run 的冒烟不代表完整任务集表现或质量优势。
